# Decisions

Why the base app is built the way it is. Add a dated entry when the group decides something.

## 2026-11-07: base app

- **Course modules only.** The professor said to use only what the modules covered. See `AGENTS.md` and `docs/module-map.md`.
- **Dependencies: only `androidx.appcompat` and `androidx.core`.** Both are in every new Android Studio project. `androidx.core` provides `NotificationCompat`, which Module 8 uses. No other libraries.
- **Android Gradle Plugin 9.4.1, Gradle 9.6.0, compileSdk/targetSdk 37, minSdk 24.** AGP 9 compiles Kotlin by itself, so there is no separate Kotlin plugin. These versions match the SDK installed on the setup PC. If a groupmate's Android Studio is older, update Android Studio rather than downgrading the project.
- **Views move with `translationY`, driven by a `Handler`.** The modules don't cover Canvas or SurfaceView, so enemies are ImageViews inside a FrameLayout. The loop runs about every 33 ms. This is fine for a few dozen enemies; don't spawn hundreds.
- **One loop, two speeds.** Movement and spawning run every frame. Machines (Auto-Turret, Drill Rig) run once per second, so their strength is easy to read: "level = damage per second" or "level = progress per second".
- **Save in `onPause`, load in `onResume`.** Survivors and Settings write straight to SQLite, so the game screen reloads everything when it comes back. Purchases also save immediately.
- **Offline earnings use the last-pause time.** The same time is used when coming back from the Survivors or Settings screen, so automation keeps working for those few seconds too. Offline time is capped at 8 hours.
- **Enemies on screen are not saved.** If Android closes the app, the current wave restarts from the beginning. This keeps the save simple.
- **Breach keeps it simple.** Lose 25% scrap, restore the hatch, repeat the wave. Survivors are never killed.
- **Survivors only boost manual work.** This keeps the automation theme clear: only machines earn while you're away.
- **Reset save needs a CheckBox.** Deleting a save can't happen with one accidental tap. Play over an existing save needs a second tap for the same reason.
- **Settings are stored in SQLite, not SharedPreferences.** SharedPreferences isn't in the modules; a small `settings` table is. Reset save keeps the settings.
- **`POST_NOTIFICATIONS` permission request.** Not a module topic, but on Android 13+ notifications don't show without it. It is one call in `MainActivity`.
- **Platform `Switch` instead of `SwitchCompat`.** Module 6 teaches `Switch`.
- **Portrait only.** The layout follows the vertical sketch.

## 2026-11-07: graphics and UI rework

- **Rooms are a cutaway, still in a ListView.** Each row draws one room with a lift shaft on the left, so new floors are just new rows. The list background draws the shaft rails, so the shaft is continuous. A footer view adds earth below the deepest room.
- **Tap the room, not a button.** The whole room is the manual action, which leaves room for the art. Workers hop and a "+N" popup shows each payout.
- **Our bunker is on the surface.** Enemies fall towards it, and survivors with the Roof job appear on its deck. Tapping the bunker repairs the hatch.
- **Upgrades open in a sheet.** The rooms stay visible most of the time. A bottom tab opens its sheet; tapping it again or ✕ closes it.
- **(Replaced by the Blender rework below.) All art is vector drawables made from code-drawn shapes,** generated by `tools/art/gen_art.py` and `tools/art/gen_ui.py`. No bitmaps, no Canvas. Some backgrounds are larger than lint's 200×200 vector advice; there are only a few on screen, so this is acceptable.
- **Less text.** Resource names became icons, labels were cut to names and numbers, and help sentences were removed.
- **Original style.** The cutaway idea is common in idle games. The bunker, rooms, characters, palette and layout here are our own; don't copy art or layouts from other games.

## 2026-11-07: name changed to Deepcell

- The game is called **Deepcell** (the user's choice). Package `com.deepcell.game`, project folder `Deepcell`, database file `deepcell.db`.
- The starting bunker is called **Bunker Nine** in the story, so the painted 9 on the bunker stays. The player can still rename the bunker.
- The emblem is now a hatch wheel around a hexagonal cell with a downward arrow.
- Because the package changed, Android treats this as a new app. A build installed under the old name (`com.burrownine.game`) stays on a device until uninstalled, and its save is not carried over.

## 2026-11-07: Blender art rework

- **Scenes are rendered in Blender, not drawn as vectors.** The user wanted a darker, lamp-lit look with depth. Every scene is built by Python scripts in `tools/blender/` (no imported models or image textures): simple bevelled shapes, procedural noise for rust and grime, banded toon lighting (Shader to RGB), inverted-hull outlines and a facing-based rim light. `render_all.py` renders, `export_to_app.py` writes WebP files to `res/drawable-nodpi/`.
- **Renders are plain images in ImageViews.** No Canvas or game engine; the app only stacks ImageViews, as before. Moving parts (workers, enemies, guards, gear, lamp glow) are still separate views animated with tweens.
- **Automation is shown by swapping the room image** (`room_dig` → `room_dig_auto`) instead of overlaying a machine.
- **Interface panels are 9-patch PNGs** generated by `tools/art/gen_ui.py` (needs Pillow), so the cut corners stay sharp at any size.
- **Font is the built-in `sans-serif-condensed`**, so no font file is bundled.
- WebP keeps the APK small (the renders are about 240 KB in total).
